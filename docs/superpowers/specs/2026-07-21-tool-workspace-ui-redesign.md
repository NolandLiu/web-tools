# 轻工具工作区 UI 调优设计

## 目标

把现有单页工具目录升级为可长期扩展的工具工作区，在不改变本地隐私处理原则和核心计算逻辑的前提下，提升导航效率、视觉一致性、工具操作效率和中英文可读性。

本次交付聚焦用户已确认的六项需求：左侧树形导航、字体／图标／按钮比例统一、工具页重排、输入输出命名、可互换工具的交换操作、字段辅助说明以及所有文本型输出的一键复制。

## 设计取向

采用「固定侧栏＋内容工作区」方案，而不是仅在现有首页增加分类按钮，也不改造成多层级路由站点。

- 桌面端：左侧 260px 固定导航，右侧为主内容；顶部保留品牌、全局搜索和语言切换。
- 平板端：侧栏缩窄，导航文字与工具列表仍保持可读。
- 移动端：侧栏收进抽屉，以菜单按钮打开；工具表单改为单列。
- 工具仍由现有注册表驱动，避免为 22 个工具复制页面结构。

## 信息架构

侧栏使用两级树形结构：

```text
全部工具
├── 单位转换
│   ├── 长度
│   ├── 重量
│   ├── 温度
│   ├── 面积
│   ├── 体积
│   ├── 速度
│   ├── 时间
│   └── 数据存储
├── 格式与开发
│   ├── JSON
│   ├── Base64
│   ├── URL
│   ├── UUID
│   ├── 时间戳
│   ├── 文本大小写
│   ├── 字数统计
│   └── 颜色转换
├── 计算工具
│   ├── 百分比
│   ├── 折扣
│   ├── BMI
│   ├── 复利
│   └── 日期间隔
└── QR Code
```

分类默认展开；当前工具具有明确高亮和 `aria-current` 状态。侧栏选择工具后直接打开工作区，不要求用户回到卡片列表。首页仍保留搜索和卡片，作为发现入口。

## 视觉系统

### 字体

不依赖外部字体请求，使用系统字体栈：

```css
Inter, ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont,
"Segoe UI", "Noto Sans SC", "Noto Sans TC", "PingFang SC",
"Microsoft JhengHei", sans-serif
```

英文和数字优先使用系统 UI 字体；简体、繁体分别由对应中文字体回退。统一行高和字重，避免英文紧凑、中文偏大的比例差。

字号层级：页面标题 40px、工具标题 32px、分区标题 20px、卡片标题 16px、正文 15px、辅助说明 13px、按钮 14px。移动端按断点收敛标题字号。

### 图标

使用一套轻量线性 SVG 图标，不再混用文本符号、单位缩写和 emoji。图标尺寸分为 16px（按钮）、18px（导航）、22px（卡片）、28px（工具标题）；图标容器统一为 40px 或 48px。

图标是辅助识别，不替代文字标签；图标按钮必须具有本地化的 `aria-label` 和 tooltip。

### 按钮

- 主按钮高度 44px，横向内边距 16px。
- 次按钮与图标按钮高度一致；仅图标按钮宽高均为 40px 或 44px。
- 复制按钮贴近对应输出，不与清空／重置混放。
- 交换按钮位于来源和目标之间；桌面显示水平双箭头，移动端旋转为垂直双箭头。
- 复制成功后按钮在 2 秒内显示「已复制／Copied」，同时提供非阻塞式 `aria-live` 提示。

## 工具页面结构

所有工具共享下列结构：

1. 面包屑：分类／工具名称。
2. 工具标题区：图标、名称、简述和本地隐私提示。
3. 操作卡片：根据工具类型渲染输入区、转换动作和输出区。
4. 辅助区：使用说明和相关工具；本次先提供结构与最少必要内容，不扩展大规模 FAQ。

### 可互换工具

适用于单位转换、温度、Base64、URL、时间戳以及可以定义双向关系的文本转换。

```text
输入值／输入内容
来源单位或输入格式
              [交换]
目标单位或输出格式
输出结果                        [复制]
```

交换操作同时交换来源和目标；在语义允许时，将当前输出带回输入以便连续转换。若输出为空或无效，仅交换选项并保留原输入。

### 单向工具

适用于 UUID、字数统计、计算器和 QR Code。输入区和输出区仍必须有清晰标题，不显示无意义的交换按钮。

## 字段命名与隐形说明

每个字段包含三层信息：

- 永久在线标签：例如「输入长度」「来源单位」「转换结果」。
- 占位提示：例如「例如：100」「粘贴要格式化的 JSON」。
- 隐形说明：使用 `aria-describedby` 连接到屏幕阅读器可读的说明；视觉上通过字段旁的信息图标提供 tooltip，而不是在页面上堆叠长段文字。

隐形说明不得只放在 `title` 属性中。tooltip 可悬停、聚焦和点击触发；移动端点击页面其他位置或按 Esc 关闭。

## 输出与复制规则

建立统一 `ResultCard` 和 `CopyButton`：

- 任意可序列化文本结果都提供复制按钮，包括单位转换、计算器、JSON、Base64、URL、UUID、时间戳、文本大小写、颜色值和统计摘要。
- 无结果或结果无效时禁用复制按钮。
- QR Code 图片保留下载按钮；同时提供复制原始输入文本，不尝试复制图片到剪贴板。
- 复制失败时显示可理解的错误提示，并保持结果可手动选择。
- 复制内容采用原始机器值，不混入标签；视觉输出可继续本地化格式。

## 组件边界

- `AppShell`：桌面侧栏、移动抽屉、主内容和顶部栏。
- `ToolSidebar`：分类树、展开状态、当前工具和键盘导航。
- `ToolHeader`：面包屑、标题、简介、隐私状态。
- `Field`：标签、输入控件、辅助说明和错误信息。
- `SwapButton`：交换语义、图标和本地化提示。
- `ResultCard`：输出标题、结果内容、复制／下载动作和状态反馈。
- `ToolWorkspace`：按现有 `ToolKind` 选择具体工具实现。

组件继续消费现有工具注册表和纯函数计算库，不把计算逻辑搬入通用 UI 组件。

## 状态与数据流

1. 搜索、卡片或侧栏选择工具，更新 `activeTool` 并记录本地打开统计。
2. 工具组件维护输入状态，调用 `src/lib/core.js` 中的纯函数得到输出。
3. `ResultCard` 接收显示值和复制值，不负责计算。
4. 语言切换重新渲染标签、说明和错误信息，不清空用户输入。
5. 移动抽屉打开状态只保存在内存，选择工具或完成导航后自动关闭。

## 错误与边界处理

- 数值输入为空、NaN、Infinity 或越界时，输出区进入明确的空／错误状态。
- 复制 API 不可用或被拒绝时，显示失败反馈，不抛出未处理异常。
- `localStorage` 不可用时，导航和工具本身仍可使用。
- 长文本不得撑破布局；结果区允许换行，代码类输出支持水平滚动。
- 侧栏树和 tooltip 必须支持键盘与触摸，不依赖 hover 才能访问。

## 响应式行为

- `>= 1100px`：固定完整侧栏，工具输入和输出可按类型双列。
- `768px–1099px`：缩窄侧栏，工具操作仍优先双列，必要时单列。
- `< 768px`：侧栏抽屉；工具输入、交换、输出纵向排列；复制按钮保持在结果标题行。
- 最低验证宽度：375px、768px、1024px、1440px。

## 测试与验收

- 保留现有核心计算测试。
- 添加组件／渲染测试，覆盖三种语言、导航树、当前工具状态、输入／输出标签和说明关联。
- 覆盖交换行为：单位选择互换、输入保留、输出更新。
- 覆盖复制状态：有结果可复制、空结果禁用、成功反馈恢复。
- 覆盖全部工具的输出动作清单，确保没有遗漏复制能力。
- 运行 `npm run lint`、`npm run test`、`npm run build`、`npm run verify`。
- 使用浏览器在四个目标宽度检查首页、典型单位工具、文本工具、计算器、QR Code，以及英文、简体中文、繁体中文。

## 非目标

- 本次不接入 AdSense、D1、KV 或新的分析服务。
- 不重写核心计算公式或本地热门排序策略。
- 不在本次引入 100+ 工具、完整 FAQ 内容库、深色模式或账户系统。
- 不创建或合并 GitHub PR，除非用户在实施完成后单独批准。
